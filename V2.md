# Environnement V2 isolé

Développer uniquement sur `v2`. Ne pas modifier `main` ni le tag `v1.0`.

Copier `config/v2/.env.example` vers `.env.v2` (ignoré par Git), puis renseigner
deux secrets aléatoires distincts de la V1. Ne jamais versionner leurs valeurs.

```powershell
docker compose --env-file .env.v2 -f compose.v2.yaml config --quiet
docker compose --env-file .env.v2 -f compose.v2.yaml up -d --build
docker compose --env-file .env.v2 -f compose.v2.yaml ps --all
```

La commande de démarrage applique les migrations existantes sur la V2 : obtenir
une autorisation avant de la lancer sur un nouvel environnement ou après ajout
de migrations. Le lanceur vérifie la base et l'utilisateur avant `migrate deploy`.

- Frontend : http://localhost:8180 ; API : http://localhost:3100.
- PostgreSQL : 127.0.0.1:5433, base `labo_echantillons_v2`, utilisateur `labo_v2`.
- Projet/réseau : `labo-echantillons-v2` ; volume :
  `labo-echantillons-v2_postgres_data`, distinct du volume V1.
- Aucun compte, seed ou contenu V1 n'est créé ou copié automatiquement.
- Les ports V2 sont exposés uniquement sur la boucle locale.
- Utiliser uniquement des fixtures synthétiques ; vérifier `current_database()`
  avant toute écriture. Les scripts de test V1 ciblant d'autres bases ne doivent
  pas être réutilisés sans adaptation et contrôle explicite.

Arrêter sans suppression :

```powershell
docker compose --env-file .env.v2 -f compose.v2.yaml stop
```

Ne pas combiner ce fichier avec `compose.yaml`. Ne jamais supprimer de volumes,
réinitialiser une base ou appliquer une migration à la V1.

Test du lanceur sans connexion PostgreSQL :
`node --test backend/docker/start-v2.test.cjs`.

Vérification PostgreSQL explicite : `node backend/test/v2-isolation.cjs`, avec
`V2_TEST_DATABASE_URL` fourni temporairement au processus, jamais enregistré dans
le code. Le script refuse toute autre cible que `127.0.0.1:5433`, base
`labo_echantillons_v2`, utilisateur `labo_v2`. Il vérifie les trois migrations,
insère un utilisateur synthétique dans une transaction annulée et compare les
empreintes des neuf tables avant/après. Son exécution exige une autorisation
d'écriture V2 ; il ne charge pas les fichiers `.env` automatiquement.
